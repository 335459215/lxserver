# 功能对照清单（能力契约）

> 计划预估"约 45 项"。勘查后实际发现 **276 项用户可见能力**（播放器 155 + 后台 121），
> 按下表口径合并为 **59 项能力契约**。合并粒度 = "可独立验收"：
> 一个契约项内部的行为要么全对要么全错，不出现"搬了一半"却通过的情况。
>
> 这份清单是新前端**唯一的功能验收依据**。每项都必须在新前端可验收，
> 且每项都要能由冒烟测试或人工步骤判定通过与否——判定不了的项不算完成。
>
> 逐项明细（含旧实现 file:line）：[`feature-detail-player.md`](feature-detail-player.md)、[`feature-detail-admin.md`](feature-detail-admin.md)

难度：`低`=静态或纯展示 / `中`=有状态或需联调 / `高`=复杂交互、音频链路、ID3、协议

## 契约使用方式

1. 新前端每完成一个 Tab，按对应 ID 逐项打勾，**未勾项不允许标记该阶段完成**。
2. 冒烟测试用例与 ID 一一对应（`scripts/smoke/cases/*.cases.mjs` 的 `id` 字段即本表 ID）。
3. "人工"验收项必须写清操作步骤与预期，不允许只写"看起来正常"。
4. 阶段 H 移除旧代码的前置条件 = 本表全部通过 + 新前端已实际使用一段时间。
